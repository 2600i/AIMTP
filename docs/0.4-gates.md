# AIMTP 0.4 Gate And Default Matrix

This is the concrete 0.4 gate/default audit from current runtime and tool code.

| Env var | Allowed values | Default | What it enables | Inert-by-default proof |
| --- | --- | --- | --- | --- |
| `INTENTOS_PROTOCOL_VERSION` | `0.4` (anything else disables 0.4 paths) | unset | Global protocol gate for 0.4 handshake/anchor/revocation/bundle flows. | With unset, 0.4 loaders return skipped/disabled and handshake endpoint remains unavailable. |
| `INTENTOS_FEDERATION` | `on`, `off` | `off` | Enables federation handshake path when paired with `INTENTOS_PROTOCOL_VERSION=0.4`. | With `off`, handshake demos print skipped and HTTP handshake path does not activate. |
| `INTENTOS_IDENTITY` | `on`, `off` | `off` | Enables identity-anchor exchange paths inside 0.4 handshake and anchor demos/loaders. | With `off`, anchor demos skip and handshake anchor exchange remains inactive. |
| `INTENTOS_HANDSHAKE_PEER_VERIFY` | `off`, `warn`, `enforce` | `off` | Adds peer possession proof checks for presented identity anchors in handshake. | With `off`, peer-proof validation is not required and baseline handshake behavior is preserved. |
| `INTENTOS_HANDSHAKE_NEGOTIATION` | `off`, `on` | `off` | Enables capability negotiation rules for handshake hello/ack capability arrays. | With `off`, negotiation failure checks are not enforced and handshake follows baseline path. |
| `INTENTOS_REVOCATIONS` | `off`, `on` | `off` | Enables revocation artifact loading for 0.4 distribution/handshake checks. | With `off`, revocation loaders return skipped and handshake revocation checks are bypassed. |
| `INTENTOS_REVOCATION_POLICY` | `off`, `warn`, `enforce` | `off` | Controls revocation handling severity when revocation checks are enabled. | With `off`, revocation validation does not reject requests and default runtime behavior stays unchanged. |
| `INTENTOS_REVOCATION_PROOF` | `off`, `on` | `off` | Enables detached revocation proof verification where supported. | With `off`, missing/invalid revocation proofs are not required for loading/apply paths. |
| `INTENTOS_TRUST_BUNDLE` | `off`, `on` | `off` | Enables trust-bundle loading/verification in 0.4 bundle paths. | With `off`, bundle loaders/verifiers report skipped/disabled and do not alter runtime trust state. |
| `INTENTOS_TRUST_BUNDLE_POLICY` | `off`, `warn`, `enforce` | `off` | Controls trust-bundle validation severity when bundle loading is enabled. | With `off`, invalid bundle input does not become a hard runtime rejection path. |
| `INTENTOS_TRUST_DISTRIBUTION` | `off`, `fs`, `http` | `off` | Selects trust distribution adapter for 0.4 artifacts (anchors/revocations/bundles). | With `off`, distribution-backed loaders remain disabled and return skipped/empty results. |
| `INTENTOS_TRUST_IDENTITY_ANCHORS_PATH` | filesystem path | unset | FS source for identity-anchor set when distribution mode is `fs`. | Unset path yields missing-source behavior without activating anchor checks by itself. |
| `INTENTOS_TRUST_HTTP_IDENTITY_ANCHORS_URL` | `http://` or `https://` URL | unset | HTTP source for identity-anchor set when distribution mode is `http`. | Unset URL yields missing-source behavior; no network path is taken unless distribution is enabled. |
| `INTENTOS_TRUST_BUNDLE_REVOCATIONS_PATH` | filesystem path | unset | FS source for revocation set when distribution mode is `fs`. | Unset path keeps revocation data absent and does not change default admission behavior. |
| `INTENTOS_TRUST_HTTP_REVOCATIONS_URL` | `http://` or `https://` URL | unset | HTTP source for revocation set when distribution mode is `http`. | Unset URL keeps revocation data absent; checks remain inactive unless explicitly gated on. |
| `INTENTOS_TRUST_BUNDLE_PATH` | filesystem path | unset | FS source for trust bundle when distribution mode is `fs`. | Unset path leaves bundle loading inactive; defaults remain unchanged. |
| `INTENTOS_TRUST_HTTP_BUNDLE_URL` | `http://` or `https://` URL | unset | HTTP source for trust bundle when distribution mode is `http`. | Unset URL leaves bundle loading inactive and avoids any distribution fetch path. |
| `INTENTOS_TRUST_BUNDLE_REVOCATIONS_PROOF_PATH` | filesystem path | unset | Optional FS source for detached revocation proof with revocation artifacts. | Ignored unless revocation proof verification is explicitly enabled. |
| `INTENTOS_TRUST_HTTP_REVOCATIONS_PROOF_URL` | `http://` or `https://` URL | unset | Optional HTTP source for detached revocation proof with revocation artifacts. | Ignored unless revocation proof verification is explicitly enabled. |
| `INTENTOS_TRUSTED_REVOCATION_KEYS_JSON` | JSON object `{ keyId: publicKeyPem }` | unset/empty map | Trusted key map used to verify revocation proofs. | Has no effect unless proof verification is enabled by `INTENTOS_REVOCATION_PROOF=on`. |
| `INTENTOS_RECEIPT_POLICY` | `off`, `warn`, `enforce` | `off` | Existing receipt policy; currently also reused by identity-anchor distribution loader severity. | With `off`, identity-anchor loader failures stay non-enforcing and runtime execution semantics remain unchanged. |
| `INTENTOS_HANDSHAKE_SEND_ANCHORS` | `off`, `inline`, `setid` | `off` | Tool-only knob for `tools/handshake-http-demo.mjs` anchor send mode. | Default `off` keeps demo at baseline handshake path without anchor exchange payloads. |
| `INTENTOS_HANDSHAKE_REVOCATION_CASE` | `off`, `peer`, `key`, `anchor` | `off` | Tool-only knob for revocation-case simulation in handshake demos. | Default `off` means demo does not force revocation-case injection behavior. |
| `INTENTOS_IDENTITY_POLICY` | `off`, `warn`, `enforce` (documented) | `off` (documented) | Reserved/documented policy name for identity checks. | Current runtime does not read this variable, so default behavior is unchanged regardless of setting. |
| `INTENTOS_IDENTITY_MAX_TIMESTAMP_SKEW_SEC` | non-negative integer seconds (documented) | `300` (documented) | Reserved/documented timestamp-skew control for identity checks. | Current runtime does not read this variable, so default behavior is unchanged regardless of setting. |

Notes:
- This table is intentionally explicit about implemented gates versus documented-but-not-consumed variables.
- All 0.4 surfaces remain opt-in; defaults preserve baseline execution and receipt behavior.
