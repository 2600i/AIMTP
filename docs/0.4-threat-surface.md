# AIMTP 0.4 Threat Surface

> **Status: NEEDS_UPDATE.** This threat summary covers the experimental 0.4
> federation surfaces, not the complete current repository or Agent Trust
> Gateway. Use [`security.md`](security.md) for current cross-project security
> boundaries.

## Trust Surfaces In 0.4
- Federation handshake (`HandshakeHello` / `HandshakeAck`) and HTTP handshake endpoint.
- Identity anchor payloads and distributed identity-anchor sets.
- Revocation-set artifacts (`peer`, `key`, `anchor`) and optional revocation proofs.
- Trust-bundle artifacts that package anchors, revocations, and optional transparency metadata.

## What Can Go Wrong
- Replay: stale handshake payloads or stale distributed artifacts reused beyond intended freshness.
- Downgrade: peers omit optional controls (proofs/capabilities) when policies are permissive.
- Spoofing: forged peer/anchor/revocation inputs presented without trusted verification material.
- Stale data: local FS/HTTP sources serve old snapshots or mismatched set IDs.
- Malicious bundle: schema-valid but operator-untrusted bundle/proof material.

## Mitigations Available Today
- Explicit env gates keep 0.4 surfaces opt-in and inert by default.
- Policy modes (`off|warn|enforce`) provide deterministic rollout from observe to reject.
- Schema validation on handshake, anchor, revocation, and bundle payloads.
- Verification hooks for peer proof possession and revocation proof signatures.
- Deterministic canonicalization/signing helpers to reduce ambiguity in signed payload checks.
- Snapshot IDs/content IDs and checkpoint-oriented trust tooling support monotonicity checks.

## Explicitly Not Solved Yet
- Global revocation propagation/consensus across independent operators.
- Multi-hop federation trust routing and transitive trust semantics.
- On-chain anchoring or external timestamp authority integration.
- Automatic trust propagation and autonomous policy updates.
- Full anti-replay guarantees beyond current nonce/timestamp/policy controls.
